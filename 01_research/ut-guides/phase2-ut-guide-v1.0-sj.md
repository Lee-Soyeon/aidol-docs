## 0. UT 진행자 가이드 (반드시 읽기)

UT(User Test)는 사용자의 행동과 생각을 관찰하여 제품 방향을 검증하기 위한 실험입니다.
모든 진행자는 동일한 방식으로 테스트를 진행해야 합니다.

이번 UT의 목적은 단순히 UI 사용성을 확인하는 것이 아니라
사용자가 AIdol 서비스를 어떤 경험으로 인식하는지 확인하는 것입니다.

특히 다음 두 경험 중 어떤 경험이 더 강하게 작동하는지를 확인합니다.

- AI 아이돌과 대화하는 경험
- AI 아이돌을 캐스팅하고 키우는 프로듀싱 경험

지난 UT에서는 진행자의 해석에 따라 설문 스케일 기준이 달라지는 문제가 있었습니다.
이번 UT에서는 아래 규칙을 반드시 지켜주세요.

---

### 0.1 사용자 행동을 유도하지 않습니다

사용자가 자연스럽게 탐색하도록 두는 것이 중요합니다.

다음과 같은 말은 하지 않습니다.

- ❌ 여기 한번 눌러보세요
- ❌ 멤버 클릭해보세요
- ❌ Explore 탭 보이세요?

대신 아래처럼 말해주세요.

- ✔ 자유롭게 사용해보세요
- ✔ 편하신 방식대로 둘러보셔도 됩니다
- ✔ 다음에 하고 싶은 것을 해보셔도 됩니다

사용자가 길을 찾지 못하는 경우에도 기능을 직접 설명하지 않습니다.

---

### 0.2 기능을 설명하지 않습니다

사용자가 헷갈리는 것도 중요한 데이터입니다.

- ❌ 이건 이런 기능이에요
- ❌ 원래 이렇게 사용하는 거예요

대신 아래처럼 대응합니다.

- ✔ 어떻게 사용하실지 한번 자유롭게 시도해보셔도 됩니다

---

### 0.3 사용자의 생각을 말하도록 요청합니다

사용자가 무엇을 생각하면서 행동하는지 파악하는 것이 중요합니다.

가능하면 아래 질문을 사용해주세요.

- 지금 어떤 생각이 드셨나요?
- 이걸 보면서 어떤 느낌이 드셨나요?
- 다음에는 무엇을 해보고 싶으세요?

---

### 0.4 설문(5점 척도) 진행 규칙

설문은 정량 데이터를 얻기 위한 질문입니다. 모든 진행자가 동일한 방식으로 질문해야 합니다.

**질문 문장은 그대로 읽습니다**

설문 질문은 가이드에 작성된 문장을 그대로 읽어주세요.

- ❌ 질문을 요약하거나 바꾸지 않습니다
- ❌ 진행자가 의미를 해석하지 않습니다

예시:

> "다음 질문입니다. 내가 만든 아이돌 그룹에 애착이 느껴졌다에 대해 1에서 5 사이 점수로 답해주세요."

**스케일 기준**

설문 시작 전에 아래 기준을 설명해주세요.

| 점수 | 기준 |
|------|------|
| 1 | 전혀 그렇지 않다 |
| 2 | 그렇지 않다 |
| 3 | 보통이다 |
| 4 | 그렇다 |
| 5 | 매우 그렇다 |

**점수 유도 금지**

- ❌ 이건 4 정도 느낌인가요
- ❌ 아까 좋아하셨으니까 5인가요

사용자가 스스로 점수를 선택하도록 합니다.

## 1. Phase 2 UT 구조

Phase 2에서는 UT를 두 종류로 나누어 진행합니다.

| UT | 목적 |
|----|------|
| Product UT | Sprint 4–6 UX 흐름 검증 |
| Experiment UT | IP 프로듀싱 가설 검증 |

Product UT는 현재 제품 경험 자체가 자연스럽게 작동하는지 확인하는 테스트이고,
Experiment UT는 제품 방향 가설을 검증하기 위한 실험입니다.

---

## 2. UT 진행 시점

Product UT는 Sprint 5 완료 후 진행합니다.

이 시점에는 아래 기능이 준비됩니다.

- 아이돌 생성
- My Group 페이지
- 콘텐츠 피드
- 좋아요
- Explore 탐색

따라서 아이돌 생성 → 콘텐츠 소비 → 탐색까지 전체 경험을 테스트할 수 있습니다.

---

## 3. UT 기본 방식

| 항목 | 내용 |
|------|------|
| 테스트 인원 | 6–8명 |
| 테스트 시간 | 약 20–30분 |
| 테스트 방식 | 사용자 직접 사용 / 화면 녹화 / 음성 녹음 / 진행자 관찰 |

---

## 4. 사용자 세그먼트

UT 참여자는 아래 세그먼트 중 하나로 분류합니다.

| 세그먼트 | 설명 |
|----------|------|
| A — 팬 / 소비형 유저 | 아이돌 콘텐츠를 소비하는 성향이 강한 사용자. 예: K-pop 팬, 아이돌 콘텐츠 소비 경험이 있는 사용자 |
| B — 창작형 유저 | 캐릭터 제작, 세계관, 콘텐츠 제작에 관심이 있는 사용자. 예: 캐릭터 창작, AI 생성 콘텐츠 관심 유저 |
| C — 일반 유저 | 특정 팬덤 경험이나 창작 경험이 없는 일반 사용자 |

---

## 5. Product UT

(Sprint 4–6 기능 검증)

### 5.1 목적

아이돌 생성 이후 사용자가 자연스럽게 다음 행동을 하는지 확인

### 5.2 목표 UX 루프

아이돌 생성 → 내 그룹 → 콘텐츠 소비 → 좋아요 → Explore 탐색

### 5.3 Task 구성

**Task 1 — 아이돌 생성**

> 아이돌 그룹을 만들어보세요

관찰 포인트

- 캐스팅 과정 몰입 여부
- 멤버 얼굴을 확인하는 행동

---

**Task 2 — My Group 확인**

> 내가 만든 그룹을 확인해보세요

관찰 포인트

- 멤버 프로필 클릭
- 이미지 확대 행동

---

**Task 3 — 콘텐츠 확인**

> 아이돌 콘텐츠를 확인해보세요

관찰 포인트

- 콘텐츠 클릭 여부
- 콘텐츠 체류 시간

---

**Task 4 — Explore 탐색**

> 다른 유저의 아이돌 그룹을 자유롭게 탐색해보세요

관찰 포인트

- Explore 진입 여부
- 그룹 카드 클릭
- 좋아요 행동

### 5.4 행동 기록 시트

응답자 ID: ______

| 행동 지표 | 기록 |
|-----------|------|
| 아이돌 생성 완료 | O / X |
| 멤버 얼굴 클릭 | O / X |
| 멤버 이미지 확대 | O / X |
| My Group 진입 | O / X |
| 콘텐츠 클릭 | O / X |
| 콘텐츠 체류 | 짧음 / 보통 / 김 |
| 좋아요 클릭 | O / X |
| Explore 진입 | O / X |
| 다른 그룹 클릭 | O / X |
| Explore 체류 | 짧음 / 보통 / 김 |

추가 관찰 메모: 사용자의 특징적인 행동이나 발화를 기록합니다.

### 5.5 인터뷰 질문

1. 지금 만든 아이돌이 어떤 느낌인가요?
2. 아이돌을 만든 다음 무엇을 해보고 싶나요?
3. 다른 유저의 아이돌 그룹을 보는 경험은 어땠나요?

### 5.6 설문 질문 (5점 척도)

1. 내가 만든 아이돌 그룹에 애착이 느껴졌다
2. 아이돌 콘텐츠를 보는 것이 재미있었다
3. 아이돌 콘텐츠에 반응(좋아요 등)을 남기고 싶었다
4. 다른 유저의 아이돌 그룹을 계속 탐색해보고 싶었다

## 6. Experiment UT

(IP 프로듀싱 가설 검증)

### 6.1 목적

사용자가 AI 아이돌과 대화하는 경험보다
아이돌을 키우고 프로듀싱하는 경험에 더 흥미를 느끼는지 확인

### 6.2 테스트 방식

채팅 화면에서 아래 메시지를 노출합니다.

> 다음 활동 컨셉을 정해보시겠어요?

선택지

- 컨셉 정하기
- 그냥 대화하기

### 6.3 Fake Door 실험 설명

이 버튼은 실제 기능이 아니라 사용자 반응을 확인하기 위한 Fake Door 실험입니다.

사용자가

- AI와 대화를 계속하려는지
- 아이돌 활동을 직접 정하려는지

행동을 통해 확인합니다.

### 6.4 행동 기록 시트

응답자 ID: ______

| 행동 지표 | 기록 |
|-----------|------|
| 채팅 시작 | O / X |
| Producer CTA 노출 | O / X |
| Producer CTA 클릭 | O / X |
| 채팅 계속 선택 | O / X |
| 컨셉 정하기 선택 | O / X |
| 알림 등록 | O / X |
| Paywall 도달 | O / X |

추가 메모:

### 6.5 인터뷰 질문

1. 아이돌과 대화하는 경험은 어땠나요?
2. 아이돌 활동을 직접 정할 수 있다면 무엇을 해보고 싶나요?
3. 아이돌을 키우는 느낌이 있었나요?

### 6.6 설문 질문 (5점 척도)

1. 내가 아이돌을 키우는 느낌이 들었다
2. 아이돌의 활동이나 컨셉을 직접 정해보고 싶다
3. 내가 만든 아이돌이 스타로 성장하는 과정을 보고 싶다
4. 아이돌을 직접 프로듀싱할 수 있다면 비용을 지불할 의향이 있다

## 7. 서비스 평가

UT 마지막에 서비스 전체 경험 기준으로 질문합니다.

### 7.1 PMF

**질문**

> 이 서비스가 더 이상 사용할 수 없게 된다면 어떤 느낌이 드실 것 같나요?

응답 선택지

- 매우 실망
- 조금 실망
- 별로 아쉽지 않음
- 사용하지 않을 것

### 7.2 재사용 의향

**질문**

> 이 서비스가 정식으로 출시된다면 다시 사용할 의향이 있으신가요?

점수: 1–5점

### 7.3 공유 의향

**질문**

> 이 서비스를 친구나 지인에게 공유하거나 소개할 의향이 있으신가요?

점수: 1–5점

### 7.4 NPS

**질문**

> 이 서비스를 친구에게 추천할 가능성은 얼마나 되나요?

점수: 0–10점

### 7.5 유료 전환 의향

**질문**

> 아이돌 프로듀싱 기능이 있다면 비용을 지불할 의향이 있으신가요?

응답: 예 / 아마도 / 아니오

## 8. 이번 UT에서 확인하려는 가설

### 가설 1 — 아이돌 캐릭터 애착

사용자는 AI와 대화하는 것보다 자신이 만든 아이돌 캐릭터에 더 큰 애착을 느낀다

지표: 멤버 클릭 / 이미지 확대 / 애착 설문 점수

### 가설 2 — 콘텐츠 소비 행동

아이돌 생성 이후 콘텐츠 소비 행동 발생

지표: 콘텐츠 클릭률 / 콘텐츠 체류

### 가설 3 — 상호작용 행동

콘텐츠 반응 행동

지표: 좋아요 클릭률

### 가설 4 — 아이돌 세계 탐색

다른 유저 그룹 탐색

지표: Explore 진입률 / 그룹 카드 클릭률

### 가설 5 — IP 프로듀싱 니즈

아이돌 채팅보다 아이돌 프로듀싱 경험 선호

지표: Producer CTA 클릭률 / 프로듀싱 설문 점수 / 지불 의향

## 9. 이번 UT의 핵심 질문

AIdol은

AI 채팅 서비스인가

아니면

AI 아이돌을 캐스팅하고 키우는 프로듀싱 경험인가

UT 결과를 통해 AIdol 서비스의 핵심 경험을 검증합니다.
