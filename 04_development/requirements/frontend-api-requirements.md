## Sprint 5

### 5. 멤버 스탯 조회

> 멤버의 현재 스탯과 등급을 확인하여
> 육성 목표와 진행 상황을 파악할 수 있다.

사용처: 멤버 프로필 스탯 탭

재사용 API: `GET /companions/{id}`

#### 5.1 필요 데이터

| 데이터      | 타입                            | 설명                 |
| ----------- | ------------------------------- | -------------------- |
| 보컬 스탯   | 숫자                            | vocal 수치 (0~200)   |
| 비주얼 스탯 | 숫자                            | visual 수치 (0~200)  |
| 매력 스탯   | 숫자                            | charm 수치 (0~200)   |
| 체력 스탯   | 숫자                            | stamina 수치 (0~200) |
| 등급        | "F" \| "D" \| "C" \| "B" \| "A" | stats 합계 기반 등급 |

기존 API 변경 요청:

| 항목            | 현재                     | Sprint 5 요구                                                    |
| --------------- | ------------------------ | ---------------------------------------------------------------- |
| stats 최대값    | 0~100                    | 0~200 (누적 상승, 감소 없음)                                     |
| grade 계산 기준 | stats 평균값             | stats 합계 (F: 0~59, D: 60~149, C: 150~299, B: 300~499, A: 500+) |
| grade enum      | "A" \| "B" \| "C" \| "F" | "F" \| "D" \| "C" \| "B" \| "A" (D 추가)                         |

### 6. 연습 크레딧 조회

> 멤버별 포토카드 생성 가능 횟수를 확인하여
> 생성 가능 여부를 사전에 파악하고 충전 여부를 결정할 수 있다.

사용처: 연습하기 메뉴, 포토카드 드로우 진입 시

#### 6.1 필요 데이터

요청 데이터:

| 데이터      | 타입        | 설명                  |
| ----------- | ----------- | --------------------- |
| 멤버 식별자 | 텍스트      | 조회 대상 멤버 ID     |
| 콘텐츠 타입 | "PHOTOCARD" | 조회 대상 콘텐츠 종류 |

응답 데이터:

| 데이터              | 타입      | 설명                                       |
| ------------------- | --------- | ------------------------------------------ |
| 무료 크레딧 잔여량  | 숫자      | 해당 멤버/타입의 무료 크레딧 잔여량 (0~3)  |
| 충전 크레딧 잔여량  | 숫자      | 사용자 단위 공유 크레딧 잔여량 (0~3)       |
| 다음 충전 가능 시각 | 날짜/시간 | 쿨다운 중이면 datetime, 그렇지 않으면 null |

#### 6.2 인수 조건

- 무료 크레딧은 멤버별, 콘텐츠 타입별 독립 관리된다
- 충전 크레딧은 사용자 단위로 관리된다 (멤버 간 공유)

### 7. 포토카드 생성

> 컨셉과 보상 모드를 선택하여 포토카드를 생성해서
> 멤버 스탯을 올리고 포토카드를 컬렉션에 추가할 수 있다.

사용처: 포토카드 드로우 화면

#### 7.1 필요 데이터

요청 데이터:

| 데이터      | 타입                                                   | 설명                            |
| ----------- | ------------------------------------------------------ | ------------------------------- |
| 멤버 식별자 | 텍스트                                                 | 포토카드 생성 대상 멤버 ID      |
| 컨셉        | "SCHOOL_LIFE" \| "FINGER_HEART" \| "DAILY" \| "RANDOM" | 선택한 포토카드 컨셉            |
| 보상 모드   | "FIXED" \| "RANDOM"                                    | 확정(+8 고정) 또는 랜덤(+2~+23) |

응답 데이터:

| 데이터           | 타입                                       | 설명                                   |
| ---------------- | ------------------------------------------ | -------------------------------------- |
| 포토카드 식별자  | 텍스트                                     | 생성된 포토카드 ID                     |
| 이미지 URL       | 이미지 URL                                 | 생성된 포토카드 이미지                 |
| 보상 등급        | "MISS" \| "NORMAL" \| "GREAT" \| "JACKPOT" | 랜덤 모드 결과 등급 (확정 모드는 null) |
| 비주얼 획득 스탯 | 숫자                                       | 이번 생성으로 획득한 비주얼 수치       |
| 매력 획득 스탯   | 숫자                                       | 이번 생성으로 획득한 매력 수치         |
| 체력 획득 스탯   | 숫자                                       | 이번 생성으로 획득한 체력 수치         |
| 총 획득 스탯     | 숫자                                       | 이번 생성에서 획득한 스탯 합계         |
| 현재 총 스탯     | 숫자                                       | 생성 후 멤버의 누적 스탯 합계          |
| Near-Miss 여부   | 참/거짓                                    | Near-Miss 연출 발동 여부               |

#### 7.2 인수 조건

- 무료 크레딧 또는 충전 크레딧이 1 이상 있어야 생성 가능
- 생성 성공 시 무료 크레딧 1회 차감 (무료 크레딧 소진 시 충전 크레딧 차감)
- 확정 모드는 비주얼 +5, 매력 +2, 체력 +1 고정 반환
- Near-Miss는 랜덤 모드 MISS 결과 시에만 true 가능하며, 세션당 최대 1회
- 포토카드 생성은 concept만 전송한다. shotType을 함께 전송하거나 concept을 생략하면 400 Bad Request

#### 7.3 경계 조건

| 상황                                | 기대 동작                    |
| ----------------------------------- | ---------------------------- |
| 크레딧 없음 (무료 + 충전 모두 소진) | 오류 반환 (크레딧 차감 없음) |
| AI 생성 실패                        | 오류 반환 (크레딧 차감 없음) |
| F등급 멤버에게 Random 컨셉 선택     | 오류 반환                    |
| shotType과 concept 동시 전송        | 400 Bad Request              |

## Sprint 6

> **설계 변경: Practice(연습) / Collectible(수집 산출물) 분리 + type/variant 패턴 도입**
>
> Sprint 6부터 연습 행위(Practice)와 수집 산출물(Collectible)을 분리하고,
> 연습 종류(type)와 세부 옵션(variant)으로 구분하는 통합 패턴을 적용한다.
> 포토카드 생성도 동일 패턴으로 통합한다
> (Sprint 5의 `POST /companions/{id}/photocards` → `POST /companions/{id}/practices` with `type: "PHOTOCARD"`).
>
> - **Practice**: 크레딧 차감 + 스탯 적립 행위. 영속 레코드 (삭제 불가).
> - **Collectible**: 연습 결과 산출물 중 사용자의 컬렉션/보관함에 저장·조회·삭제 가능한 항목.
>   삭제해도 해당 Practice로 획득한 스탯은 유지된다.
>
> | type      | variant                                                   | 산출물 |
> | --------- | --------------------------------------------------------- | ------ |
> | PHOTOCARD | "SCHOOL_LIFE" \| "FINGER_HEART" \| "DAILY" \| "RANDOM"   | 이미지 |
> | SHOT      | "SIDE" \| "FULL"                                          | 이미지 |
> | VOICE     | TBD                                                       | 오디오 |
> | DANCE     | TBD                                                       | 영상   |

### 11. 연습 생성 (통합 엔드포인트)

> 연습 종류(포토카드·샷 등)와 세부 유형을 선택하여 이미지를 생성해서
> 멤버 스탯을 올리고 컬렉션에 산출물을 추가할 수 있다.

사용처: 포토카드 만들기 화면, 측면/전신 샷 만들기 화면

신규 API: `POST /companions/{id}/practices`

> Sprint 5의 `POST /companions/{id}/photocards`를 이 엔드포인트로 통합한다
> (`type: "PHOTOCARD"`로 동일하게 요청).
> 향후 보이스·댄스도 동일 패턴으로 확장한다.

#### 11.1 필요 데이터

요청 데이터:

| 데이터      | 타입                        | 설명                                |
| ----------- | --------------------------- | ----------------------------------- |
| 멤버 식별자 | 텍스트                      | 이미지 생성 대상 멤버 ID (URL path) |
| 연습 종류   | "PHOTOCARD" \| "SHOT"       | 포토카드 또는 샷 촬영               |
| 세부 유형   | 텍스트                      | type별 세부 옵션 (아래 참고)        |
| 보상 모드   | "FIXED" \| "RANDOM"         | 확정(+8 고정) 또는 랜덤(+2~+23)    |

> type별 유효한 variant:
> - `type: "PHOTOCARD"` → variant: `"SCHOOL_LIFE" | "FINGER_HEART" | "DAILY" | "RANDOM"`
> - `type: "SHOT"` → variant: `"SIDE" | "FULL"`
>
> 요청 구조 예시:
> - `{ type: "PHOTOCARD", variant: "DAILY", mode: "RANDOM" }`
> - `{ type: "SHOT", variant: "SIDE", mode: "FIXED" }`
>
> - type이 연습 종류를 결정하고, variant가 type별 세부 옵션을 지정한다
> - type별 유효한 variant 집합은 백엔드에서 검증한다
> - type 또는 variant 누락, 잘못된 조합 시 400 Bad Request

응답 데이터:

| 데이터           | 타입                                       | 설명                                   |
| ---------------- | ------------------------------------------ | -------------------------------------- |
| 산출물 식별자    | 텍스트                                                   | 생성된 컬렉터블 ID                            |
| 이미지 URL       | 이미지 URL                                               | 생성된 이미지 (프레임 없는 원본)              |
| 연습 종류        | "PHOTOCARD" \| "SHOT"                                    | 요청한 type echo                              |
| 세부 유형        | 텍스트                                                   | 요청한 variant echo                           |
| 보상 등급        | "MISS" \| "NORMAL" \| "GREAT" \| "JACKPOT" \| null       | 랜덤 모드 결과 등급 (확정 모드는 null)        |
| 비주얼 획득 스탯 | 숫자                                                     | 이번 생성으로 획득한 비주얼 수치              |
| 매력 획득 스탯   | 숫자 \| null                                             | 이번 생성으로 획득한 매력 수치 (SHOT은 null)  |
| 체력 획득 스탯   | 숫자                                                     | 이번 생성으로 획득한 체력 수치                |
| 총 획득 스탯     | 숫자                                                     | 이번 생성에서 획득한 스탯 합계                |
| 현재 총 스탯     | 숫자                                                     | 생성 후 멤버의 누적 스탯 합계                 |
| 현재 등급        | "F" \| "D" \| "C" \| "B" \| "A"                         | 생성 후 멤버의 현재 등급                      |
| 현재 스탯        | 객체 (vocal, dance, rap, visual, stamina, charm)         | 생성 후 멤버의 종목별 누적 스탯               |
| Near-Miss 여부   | 참/거짓                                                  | Near-Miss 연출 발동 여부                      |

> type별 적립 스탯:
> - PHOTOCARD: 비주얼, 매력, 체력
> - SHOT: 비주얼, 체력 (매력 스탯 변동 없음 → null 반환)
>
> `현재 총 스탯`, `현재 등급`, `현재 스탯`은 Practice/Collectible 영속 모델 필드가 아니라
> 연습 결과 화면 갱신을 위한 Companion 상태 스냅샷이며,
> 추가 조회 없이 한 응답에 포함되어야 한다.

#### 11.2 인수 조건

- 무료 크레딧 또는 충전 크레딧이 1 이상 있어야 생성 가능
- 생성 성공 시 무료 크레딧 1회 차감 (무료 크레딧 소진 시 충전 크레딧 차감)
- 확정 모드 고정 반환: PHOTOCARD는 비주얼·매력·체력 (합계 +8), SHOT은 비주얼·체력 (합계 +8, 매력 없음)
- 무료 크레딧은 연습 종류별로 독립 관리 (PHOTOCARD와 SHOT 각각 멤버당 3회 무료 부여)
- Near-Miss는 랜덤 모드 MISS 결과 시에만 true 가능하며, 세션당 최대 1회
- PHOTOCARD의 variant `"RANDOM"`은 F등급 멤버에게 선택 불가

#### 11.3 경계 조건

| 상황                                | 기대 동작                    |
| ----------------------------------- | ---------------------------- |
| 크레딧 없음 (무료 + 충전 모두 소진) | 오류 반환 (크레딧 차감 없음) |
| AI 생성 실패                        | 오류 반환 (크레딧 차감 없음) |
| type에 유효하지 않은 variant 전송   | 400 Bad Request              |
| type 또는 variant 누락              | 400 Bad Request              |
| F등급 멤버에게 PHOTOCARD RANDOM     | 오류 반환                    |

### 15. 캐스팅 멤버 민족(Ethnicity) 저장

> 프로필 이미지 생성 시 인종/외모 특성이 반영된 이미지를 생성할 수 있다.

사용처: 캐스팅 Step 01 (성별 + 민족 선택 화면)

기존 API 변경 요청: `PATCH /companions/{id}` (멤버 프로필 업데이트)

| 항목            | 현재         | Sprint 6 요구                                            |
| --------------- | ------------ | -------------------------------------------------------- |
| 업데이트 필드   | gender 포함  | ethnicity enum 값 확장 (혼혈 키 `KOR_JPN/RUS/USA/CAN` 추가) |

#### 15.1 필요 데이터

요청 데이터 (추가):

| 데이터 | 타입 | 설명 |
| ------ | ---- | ---- |
| 민족   | "EAST_ASIAN" \| "SOUTHEAST_ASIAN" \| "EUROPEAN" \| "SOUTH_AMERICAN" \| "KOR_JPN" \| "KOR_RUS" \| "KOR_USA" \| "KOR_CAN" | 선택한 민족 분류 (단일 enum 값) |

> 모든 키는 단일 enum으로 평탄하게 정의한다. "혼혈" 자체는 enum 값으로 존재하지 않으며, 한-일/한-러/한-미/한-캐는 각각의 단일 키(`KOR_JPN`, `KOR_RUS`, `KOR_USA`, `KOR_CAN`)로 전송된다.
> 프론트엔드는 UI상으로만 1단계 칩(동아시아·동남아시아·유럽·남미·혼혈)을 노출하고, "혼혈" 선택 시 하단에 2단계 서브 칩(한-일·한-러·한-미·한-캐)을 visible 표시한다. 사용자가 서브 칩까지 선택해야 해당 평탄화 키가 전송된다.

> 요청 예시:
> - 단일 민족: `{ ethnicity: "EAST_ASIAN" }`
> - 혼혈 (한-일): `{ ethnicity: "KOR_JPN" }`

#### 15.2 인수 조건

- 성별과 민족은 Step 01에서 함께 저장 (별도 요청 또는 한 번에 전송 가능)
- 프론트엔드는 1단계에서 "혼혈" 선택 시, 2단계 서브 칩까지 선택해야 다음 단계로 진행시킨다 (서브 칩 미선택 상태에서 저장 요청 차단)
- 저장된 ethnicity 값은 Step 03 프로필 이미지 생성 시 프롬프트에 자동 반영

#### 15.3 경계 조건

| ----------------------------- | --------------- |
| ethnicity 누락 또는 빈 문자열 | 400 Bad Request |
| 유효하지 않은 ethnicity 값    | 400 Bad Request |

### 16. 캐스팅 프로필 이미지 생성 프롬프트 자동 반영

> Step 03에서 선택한 분위기·인상·헤어스타일 칩이 이미지 생성 프롬프트에 반영되어
> 비전문 사용자도 원하는 프로필 이미지를 쉽게 생성할 수 있다.

사용처: 캐스팅 Step 03 (프로필 이미지 생성 화면)

재사용 API: `POST /companions/images`

#### 16.1 필요 데이터

요청 데이터:

| 데이터        | 타입   | 설명                                                    |
| ------------- | ------ | ------------------------------------------------------- |
| 멤버 식별자   | 텍스트 | 대상 멤버 ID                                            |
| 분위기        | 텍스트 | 선택한 분위기 칩 키 (예: "CUTE", "COOL" 등)             |
| 인상          | 텍스트 | 선택한 인상 칩 키                                       |
| 헤어스타일    | 텍스트 | 선택한 헤어스타일 칩 키                                 |

> 프론트엔드는 칩 선택 키만 전송하고, 프롬프트 조립은 백엔드가 전담한다.
> 백엔드는 칩 키 → 영어 프롬프트 매핑 + companion의 gender·ethnicity 주입까지 프롬프트 전체를 조립한다.
> 이를 통해 프롬프트 변경 시 백엔드만 수정하면 웹·앱 모두 반영된다.

응답 데이터:

| 데이터               | 타입                                                                                                                  | 설명                                       |
| -------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 이미지 URL           | 이미지 URL                                                                                                            | 생성된 프로필 이미지                       |
| 적용된 성별          | "MALE" \| "FEMALE"                                                                                                    | 실제 프롬프트에 주입된 gender 값 (echo)    |
| 적용된 민족          | "EAST_ASIAN" \| "SOUTHEAST_ASIAN" \| "EUROPEAN" \| "SOUTH_AMERICAN" \| "KOR_JPN" \| "KOR_RUS" \| "KOR_USA" \| "KOR_CAN" | 실제 프롬프트에 주입된 ethnicity 값 (echo) |

> 응답에 실제 주입된 gender·ethnicity를 echo하여 프론트엔드가 검증·디버그할 수 있도록 한다.

#### 16.2 인수 조건

- 프론트엔드는 분위기·인상·헤어스타일 칩 키만 전송한다
- 백엔드가 칩 키 → 영어 프롬프트 매핑 및 companion의 gender·ethnicity 자동 주입을 포함한 프롬프트 전체를 조립한다
- gender 또는 ethnicity가 저장되지 않은 상태에서 요청하면 400 Bad Request를 반환하며, 오류 응답에 누락된 필드명을 포함한다
- 응답에 실제 주입된 gender·ethnicity 값을 echo한다
- 이미지 재생성 시 동일 옵션으로 재시도 가능 (횟수 제한 없음, 캐스팅 단계는 과금 범위 외)

#### 16.3 경계 조건

| 상황                                      | 기대 동작                                          |
| ----------------------------------------- | -------------------------------------------------- |
| companion에 gender가 저장되지 않은 상태      | 400 Bad Request (오류 응답에 누락 필드 포함)        |
| companion에 ethnicity가 저장되지 않은 상태   | 400 Bad Request (오류 응답에 누락 필드 포함)        |
| gender·ethnicity 모두 저장되지 않은 상태     | 400 Bad Request (오류 응답에 누락 필드 목록 포함)   |
| 유효하지 않은 칩 키 전송                     | 400 Bad Request                                     |
| 칩 키 누락 (분위기·인상·헤어스타일 중 하나)  | 400 Bad Request                                     |
