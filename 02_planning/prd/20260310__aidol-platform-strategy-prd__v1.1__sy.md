## 1. Executive Summary

### 1.1 Vision

**알로라는 "내가 만든 AI 아이돌이 매일 살아가는 세계"다.**

사용자는 단순히 캐릭터를 생성하는 것이 아니라, 하나의 아이돌 그룹을 캐스팅하고 지켜보는 **기획사 대표**가 된다. 핵심은 "내가 접속하지 않아도 아이돌의 하루가 계속된다"는 감각이다. 다시 들어오면 숙소에서 있었던 일, 연습 영상, 멤버 간 에피소드, 새로운 피드를 확인한다.

### 1.2 우리는 무엇이 아닌가

- ❌ 시뮬레이션 게임
- ❌ 1:1 AI 컴패니언 앱
- ❌ 단순 AI 캐릭터 생성 툴
- ❌ 콘텐츠 제작용 B2B SaaS

### 1.3 이번 수정의 핵심

기존 v1.0은 Phase 2를 너무 빠르게 **UGC 플랫폼 / 수익화 / PMF 설문** 중심으로 상정했다. 하지만 최근 UT와 인터뷰 준비를 거치며, Sprint 5-6에서 먼저 만들어야 할 것은 거대한 플랫폼이 아니라 아래 두 가지임이 명확해졌다.

1. **살아있는 세계의 증거** — 피드/하이라이트/자동 생성 콘텐츠
2. **돌아올 이유** — 육성, 친밀도, 일일 루프, 다음 에피소드 기대감

즉, Sprint 5-6의 목적은 "대규모 플랫폼 기능"이 아니라 **세계의 실재감 + 장기 리텐션 루프**를 검증하는 것이다.

## 2. Product Reframe

### 2.1 문제 재정의

Phase 1에서 확인한 가장 큰 문제는 이것이다.

> **"만들기는 재밌는데, 만들고 나서 뭐 하지?"**

캐스팅 경험 자체의 몰입도는 높았지만, 그룹 생성 직후 사용자가 할 일이 급격히 줄어든다. 이때 제품이 게임처럼 추가 조작을 요구하면 피로감이 커지고, 챗봇처럼 1:1 대화만 반복하면 세계의 스케일감이 사라진다.

### 2.2 해결 방향

이 공백을 메우는 핵심 루프는 아래와 같다.

```text
내 그룹 생성
→ 아이돌들이 스스로 활동/대화/콘텐츠 생성
→ 사용자는 피드로 아이돌의 하루를 확인
→ 특정 멤버/에피소드에 감정 이입
→ 채팅/육성/미션으로 개입
→ 다음 에피소드를 기대하며 재방문
```

### 2.3 Sprint 5-6에서 검증할 핵심 가설

#### 가설 A. 살아있는 감각
> 사용자가 "내가 없어도 아이돌이 살아가고 있다"고 느끼면 재방문한다.

#### 가설 B. 보호 본능과 애착
> 사용자가 특정 멤버/그룹에 애착을 느끼면 피드를 반복 확인하고 더 깊이 개입한다.

#### 가설 C. 육성 루프
> 사용자가 세계에 개입한 흔적(친밀도, 미션, 성장)이 쌓이면 장기 리텐션이 높아진다.

## 3. Product Principles

### 3.1 Principle 1 — 세계가 먼저 움직여야 한다
사용자가 무언가를 하지 않아도, 아이돌의 하루가 먼저 생성되어야 한다. 피드는 단순 콘텐츠 리스트가 아니라 **세계가 흘러가고 있다는 증거**다.

### 3.2 Principle 2 — 관계성은 1:1이 아니라 그룹 단위에서 느껴져야 한다
알로라의 차별점은 멤버 간 관계와 그룹의 케미다. Sprint 5-6은 이 관계성을 채팅 한 화면이 아니라 **피드 에피소드, 활동 상태, 하이라이트**로 먼저 체감시켜야 한다.

### 3.3 Principle 3 — 개입은 가볍지만 의미 있어야 한다
사용자가 하루 종일 조작해야 하는 게임이 되어서는 안 된다. 대신 체크인, 미션, 응원, 친밀도 상승처럼 **짧은 개입이 큰 감정적 보상으로 이어지는 구조**여야 한다.

### 3.4 Principle 4 — 수익화보다 실재감과 리텐션이 우선이다
Sprint 5-6은 결제 기능 확장보다, **왜 사용자가 다시 돌아오는지**를 먼저 증명해야 한다. 과금은 이 루프가 작동한 뒤에 붙는 게 맞다.

## 4. Sprint 4-6 Product Roadmap

### 4.1 Sprint 4의 역할 — 피드 인프라 기초

Sprint 4는 다음의 기반을 만든다.

- `GET /aidol-feeds` API 정의
- `aidol_feeds` 데이터 모델 정의
- MyGroup / OtherGroup 피드 탭에서 사용할 리스트 조회 기반 마련

즉 Sprint 4는 **"아이돌의 일상을 담는 그릇"**을 만드는 단계다.

### 4.2 Sprint 5의 역할 — 살아있는 세계를 보여주는 단계

Sprint 5는 사용자가 실제로 다음을 경험하게 해야 한다.

- 내 아이돌의 하루가 새 피드로 올라온다
- 피드마다 에피소드 성격이 다르다 (연습, 숙소, 멤버 케미, 공지 등)
- 새 피드를 확인하는 행위 자체가 홈/피드의 핵심 사용 이유가 된다

즉 Sprint 5의 질문은 이것이다.

> **"사용자는 피드를 보며 아이돌이 진짜 살아간다고 느끼는가?"**

### 4.3 Sprint 6의 역할 — 사용자를 다시 돌아오게 만드는 단계

Sprint 6은 세계를 보는 것에서 한 걸음 더 나아가, 사용자가 세계에 **개입하고 관계를 쌓는 루프**를 만든다.

- 체크인/미션을 통해 매일 돌아올 이유 제공
- 특정 멤버/그룹에 대한 친밀도 누적
- 사용자 행동이 다음 에피소드나 보상에 연결됨

즉 Sprint 6의 질문은 이것이다.

> **"사용자는 이 세계에 개입할수록 더 자주 돌아오는가?"**

## 5. Sprint 5 PRD — Living World Feed

### 5.1 Sprint Goal

**"내 아이돌이 오늘도 살아갔다"는 감각을 피드 경험으로 전달한다.**

### 5.2 In Scope

#### 5.2.1 피드 콘텐츠 생성/노출
- MyGroup 피드 탭에서 내 그룹의 신규 피드 목록 조회
- OtherGroup 피드 탭에서 다른 그룹의 공개 피드 목록 조회
- 최신순 정렬 기본값 제공
- 그룹/아이돌 기준 필터링 지원
- 이미지/영상 타입 피드 지원

#### 5.2.2 에피소드 타입 정의
Sprint 5 기능 명세서에서는 최소 아래 유형을 다뤄야 한다.
- **숙소 일상**: 하루의 소소한 에피소드
- **연습/준비**: 연습실, 데뷔 준비, 촬영 준비
- **멤버 케미**: 둘 이상의 멤버 관계가 드러나는 에피소드
- **공식 소식**: 데뷔, 스케줄, 팬에게 보여줄 공지형 업데이트

#### 5.2.3 피드 카드/상세 경험
- 썸네일, 대표 문구, 생성 시각, 관련 그룹/멤버 정보 표시
- 피드 카드 탭 시 상세 보기 진입
- 상세에서 에피소드의 맥락과 미디어를 읽을 수 있어야 함
- 읽음 전/후 상태 또는 새 콘텐츠 표식 필요

#### 5.2.4 홈 진입 동기 강화
- 홈/메인 화면에서 신규 피드 존재를 인지할 수 있어야 함
- "새로운 하루가 생겼다"는 성격의 CTA 또는 배지 제공
- 피드 0개 상태(초기 생성 직후 / 아직 생성 중) 처리 필요

### 5.3 User Stories

**US-S5-1: 내 그룹의 새 하루 확인**
```text
As a 그룹 생성자,
I want to 내 그룹의 새 피드를 홈에서 바로 확인하면,
So I can 내가 없는 동안 아이돌에게 무슨 일이 있었는지 알 수 있다.
```

**US-S5-2: 멤버 관계성 소비**
```text
As a K-pop 팬,
I want to 멤버들 간 케미가 드러나는 에피소드를 피드로 읽으면,
So I can 그룹이 실제로 살아 움직인다고 느낄 수 있다.
```

**US-S5-3: 다른 그룹 탐색**
```text
As a 탐색형 사용자,
I want to OtherGroup 피드에서 다른 그룹의 일상도 보면,
So I can 세계가 내 그룹 하나에만 갇혀 있지 않다고 느낄 수 있다.
```

**US-S5-4: 신규 콘텐츠 인지**
```text
As a 재방문 사용자,
I want to 새 피드가 생겼다는 신호를 빠르게 받으면,
So I can 오늘 돌아올 이유를 즉시 이해할 수 있다.
```

## 6. Sprint 6 PRD — Nurture & Return Loop

### 6.1 Sprint Goal

**사용자가 세계를 보기만 하는 단계를 넘어, 매일 개입하고 관계를 쌓도록 만든다.**

### 6.2 In Scope

#### 6.2.1 친밀도/애착 누적
- 멤버 또는 그룹 단위 친밀도 포인트 개념 도입
- 채팅, 피드 소비, 체크인, 미션 수행 등으로 친밀도 상승
- 친밀도 상태가 사용자에게 가시적으로 표현되어야 함

#### 6.2.2 일일 체크인/미션
- 하루 단위로 돌아올 이유를 제공하는 가벼운 미션
- 예: 피드 1개 보기, 채팅 3회, 특정 멤버 반응 확인
- 보상은 세계관 친화적이어야 함 (친밀도, 특별 피드, 추가 에피소드 등)

#### 6.2.3 피드 → 개입 루프
- 피드 소비 후 사용자가 바로 할 수 있는 다음 행동이 있어야 함
- 예: 해당 멤버와 대화, 응원/격려, 오늘 일정 확인, 다음 에피소드 예고
- "읽고 끝"이 아니라 "읽고 개입" 구조로 전환

#### 6.2.4 재방문 설계
- 하루가 지나면 다시 확인할 이유가 생겨야 함
- 새로운 에피소드 예고, 미션 리셋, 친밀도 성장 표시 등 재방문 장치 필요

### 6.3 User Stories

**US-S6-1: 매일 체크인**
```text
As a 바쁜 사용자,
I want to 하루 1~3분만 투자해도 내 아이돌 세계에 개입할 수 있으면,
So I can 부담 없이 매일 돌아올 수 있다.
```

**US-S6-2: 애착 누적 확인**
```text
As a 애정형 팬,
I want to 내가 특정 멤버와 가까워지고 있다는 신호를 보면,
So I can 계속 그 멤버를 챙기고 싶어진다.
```

**US-S6-3: 피드 이후 행동 연결**
```text
As a 피드 소비자,
I want to 에피소드를 본 직후 자연스럽게 다음 행동을 제안받으면,
So I can 세계 안에서 더 깊게 놀 수 있다.
```

**US-S6-4: 다시 돌아올 이유 확보**
```text
As a 재방문 사용자,
I want to 내일 또 확인해야 할 이유가 남아 있으면,
So I can 서비스가 내 루틴에 들어온다.
```

### 6.4 Functional Requirements

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| S6-FR-1 | 친밀도 또는 유사한 관계 지표가 사용자에게 노출되어야 한다 | P0 |
| S6-FR-2 | 일일 단위 미션/체크인 구조가 있어야 한다 | P0 |
| S6-FR-3 | 피드 상세 또는 소비 완료 후 다음 행동 CTA가 있어야 한다 | P0 |

## 9. Risks & Mitigations

| 리스크 | 영향 | 대응 |
|-------|------|------|
| 피드가 단순 갤러리처럼 보임 | 세계 실재감 약화 | 에피소드 맥락/관계성/시간성 강조 |
| 피드 생성이 늦거나 품질이 낮음 | 첫인상 저하 | 초기엔 수동 큐레이션/템플릿 기반 fallback 허용 |
| 육성 시스템이 게임화 과잉으로 흐름 | 진입장벽 상승 | 1~3분 루프, 가벼운 체크인 중심 유지 |
| 수익화 요구가 먼저 들어옴 | 제품 본질 흐림 | Sprint 5-6은 리텐션 검증 우선 원칙 유지 |
