## 1. 개요 (Overview)

### 1.1 문제 정의 (Problem Statement)

현재 AIdol은 아이돌 **생성 경험**만 제공하며, 생성 이후 아이돌이 활동하는 세계 경험이 없다.

**핵심 UX 단절 지점**

현재 흐름:

```
아이돌 생성 → 완료 화면 → 종료
```

사용자는 생성 완료 후 다음 행동 단서를 찾지 못하고 서비스를 이탈한다.

**사용자 발화 근거 (Sprint 1 UT, Sprint 1-2 UT)**

> "캐스팅을 하고 물론 이제 계속 메일로 어떤 스토리가 있는지 보여지겠지만 뭔가 제가 직접 트레이닝하고 좀 키우는 느낌은 조금 부족하다는 생각은 있었어요."
> — U8 김현조 (Sprint 1-2 UT, 서비스 평가)

> "성공하려면 콘텐츠가 있어야 한다."
> — U4 배나영 (Sprint 1 UT, 그룹 완성 후)

> "이게 키우는 게임이면 이메일 작성 했을 것."
> — U7 최지윤 (Sprint 1 UT, 전환 조건 제안)

생성 이후 활동 경험이 없으면 사용자는 "만들고 끝"이라는 1회성 경험으로 인식하며, 이는 리텐션과 결제 전환의 핵심 장벽이다.

> "사실 연습생 갖고는 할 게 없어."
> — U1/U2 찬찬 (Sprint 1 UT, 생성 이후 경험 부재)

> "그런 부분이 좀 있으면은 이제 뺏기면 안 되겠다 생각이 좀 더 들 것 같은 생각은 들었습니다."
> — U8 김현조 (Sprint 1-2 UT, 36:05 / 육성 요소 부재 시 소유감·재방문 동기 미발생을 직접 진단)

> "육성이 메인이고 사이사이 얘네가 어떤 일들이 있었는지 궁금한 거지 그것만 기능이 있으면 어느 순간 질려버릴 것임."
> — U9 조수연 (Sprint 1-2 UT, 콘텐츠 단독 구조의 리텐션 한계)

U14 송선재는 그룹 완성 후 URL 공유만 요청하고 이메일을 입력하지 않았다. 만족감은 있었으나 재방문으로 이어지는 동기가 없었음을 보여주는 행동 관찰이다.

**탐색 UX 문제 (캐스팅 단계)**

계약 완료 연습생이 캐스팅 리스트 상단에 노출되는 구조 문제가 반복 관찰됐다.

> "계약완료된 사람이 너무 많아요. 이런 경우엔 어떻게 하는거람..?"
> — U11 이지현 (Sprint 1 UT, 캐스팅 탐색 중)

> "계약 완료 의미는 알겠는데 계약 미완료인 캐릭터를 바로 앞에서 보거나 필터 버튼이 있었으면 좋겠음."
> — U12 이정인 (Sprint 1 UT, 캐스팅 UX 평가)

> "퍼즐 끼워 맞춘 느낌."
> — U7 최지윤 (Sprint 1 UT, 캐스팅 과정 평가)

탐색 혼란이 캐스팅 몰입 자체를 방해하고 있으며, 이는 H1(캐릭터 애착) 검증의 선행 조건이다.

### 1.2 해결책 (Solution)

Phase 2에서는 3가지 경험을 구축한다.

1. **생성 → 콘텐츠 경험 연결**: 완료 후 내 그룹 페이지로 자연스럽게 이동
2. **아이돌 세계 탐색**: 다른 유저 그룹 탐색 및 콘텐츠 소비
3. **IP 프로듀싱 니즈 검증**: Fake Door 실험으로 채팅 vs 육성 방향 검증

목표 흐름:

```
아이돌 생성 → 내 그룹 → 콘텐츠 소비 → 탐색 → 상호작용 → (IP 프로듀싱 개입)
```

| 항목 | 내용 |
|------|------|
| 대상 | 그룹 카드, 피드 콘텐츠, 멤버 프로필 |

Sprint 1/1-2 UT에서 좋아요 기능에 대한 직접 발화는 관찰되지 않았다. 다만 아래 간접 신호들이 플랫폼 상호작용 니즈를 시사한다.

> "내가 캐스팅한 그룹이 통째로 막상 다른 유저가 가져가면 아쉽지."
> — U9 조수연 (Sprint 1-2 UT, 타인 반응에 대한 소유감 및 인정 욕구)

> "내가 홍보한다."
> — U6 김민지 (Sprint 1 UT, 내 그룹을 외부에 알리려는 능동적 행동 의도)

> (다른 유저 그룹 탐색 및 비교에 긍정 반응, 다른 유저 그룹과 경쟁/비교 욕구 발화)
> — U8 김현조 (Sprint 1-2 UT, 플랫폼 상호작용 맥락)

**기능 제안 목적**: 좋아요는 직접 검증된 니즈가 아닌, 플랫폼으로서의 사용자 상호작용 동기를 확인하기 위한 최소 단위 실험이다. Phase 2 Product UT에서 아래를 검증한다.

- 사용자가 타인의 콘텐츠에 자발적으로 반응 행동을 하는가
- 내 그룹에 좋아요가 달릴 때 리텐션 동기로 작동하는가

#### 4.2.2 그룹 카드 UX 개선

| 항목 | 내용 |
|------|------|
| 개선 사항 | 멤버 얼굴 강조, 카드 이미지 확대, 카드 레이아웃 개선 |

#### 4.2.3 홈 / 발견 탭 개선

홈 화면 추천 그룹 노출.

카드 구성:
- 그룹 이미지
- 멤버 얼굴
- 좋아요 수

#### 4.2.4 Fake Door 실험 — IP 프로듀싱 CTA

채팅 인터페이스에서 다음 CTA 노출:

```
다음 활동 컨셉을 정해보시겠어요?

[컨셉 정하기]  [그냥 대화하기]
```

컨셉 정하기 선택 시:
- 알림 등록형: "프로듀서 기능은 준비 중입니다. 출시 알림을 받으시겠어요?"
- 지불 의향형: "프로듀서 기능 / 월 3,000원" (Paywall)

실험 배경:
> "육성이 메인이고 사이사이 얘네가 어떤 일들이 있었는지 궁금한 거지 그것만 기능이 있으면 어느 순간 질려버릴 것임."
> — U9 조수연 (Sprint 1-2 UT, 콘텐츠 구조 제안)

> "내가 홍보한다."
> — U6 김민지 (Sprint 1 UT, 능동적 소유 의식)

### 4.3 Sprint 6 — Discovery

**목표**: 아이돌이 활동하는 세계 탐색 경험 구축

#### 4.3.1 Explore Feed 구축

| 항목 | 내용 |
|------|------|
| 구성 | 인기 콘텐츠, 추천 그룹, 활동 콘텐츠 |

근거:
> "글보다는 다른 그룹이 좀 어떻게 형성돼 있고 어떤 멤버가 있는지가 좀 더 궁금하다."
> — U14 송선재 (Sprint 1-2 UT, Explore 콘텐츠 선호)

> "다른 유저에게 가면 아쉽다."
> — U1/U2 찬찬 (Sprint 1 UT, 경쟁 심리)

#### 4.3.2 콘텐츠 자동 생성 (기술 검증)

아이돌 생성 이후 데뷔 인사 이미지, 첫 활동 콘텐츠 자동 생성.

#### 4.3.3 AI 인사 영상 (기술 검증)

아이돌 멤버 인사 영상: "안녕하세요 저는 ○○입니다" 형태.

#### 4.3.4 콘텐츠 피드 확장

My Group Feed → Explore Feed 연결.
