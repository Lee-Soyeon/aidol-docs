# [ 260425 ] 전체 회의 미팅록

- 일시: 2026-04-25 (토) 약 57분
- 참석자: 소연님, 영욱님, 수지님, 현준님, 지영님, 은재님, 제형님
- 불참: 미진님 (댓글로 Sprint 7 기능 명세 기반 디자인 요청 전달)

---

> **TL;DR**: UT에서 드러난 캐스팅·온보딩 UX 병목을 5/2 오프라인 테스트 전까지 우선 보완하고, 혼혈 옵션 정의·문서 접근성·개발 병렬화 방식까지 함께 정리했다. 수요일 야간 미팅은 슬랙 스레드 공유로 대체하고, 전체 미팅은 토요일 오전 11시로 고정. 5/2(토) [SMTR25 'Reply High School' 팬미팅](https://news.nate.com/view/20260220n18787) 현장(올림픽공원 올림픽홀)에서 게릴라 사용자 섭외를 진행한다.

## 요약
- 수지님은 Sprint 5까지 개발된 기능 기준으로 4명 UT를 진행 중이며, 3개 리포트는 이미 공유됐고 1개는 추가 정리 예정이라고 공유했다. 핵심 문제는 사용자가 안내 없이 서비스에 들어왔을 때 캐스팅, 채팅, 연습, 컬렉션 등 핵심 기능으로 자연스럽게 이동하지 못하는 UX 흐름이었다.
- 특히 캐스팅 플로우에서 멤버를 한 명 담은 뒤 다시 탐색으로 돌아가는 흐름, 이미 담긴 멤버가 잘 들어갔는지 확인할 수 있는 피드백, 그룹 페이지 진입 후 다음 행동을 안내하는 장치가 부족하다는 점이 주요 병목으로 정리됐다.
- 현준님은 발견 탭을 누르는 순간 그룹 생성이 시작되는 현재 구조가 사용자 액션을 충분히 설명하지 못한다고 짚었고, 그룹 생성 시작 액션을 더 명확히 분리하거나 드러낼 필요가 있다고 제안했다.
- 지영님은 Sprint 6에서 캐스팅 UI 강화 작업을 진행 중이며, 캐스팅 인종 옵션의 `혼혈 / mixed` 항목이 기획·피그마와 백엔드 구현 사이에서 정의가 맞지 않는 문제가 있다고 공유했다. 제형님도 프론트와 백엔드 중 어디서 어떤 방식으로 처리할지 아직 정리되지 않았다고 설명했다.
- 병목 논의에서는 소연님 부재로 인한 의사결정 공백, 문서 구조 파악 난이도, PR 단위가 커서 병렬 개발이 어려워지는 문제가 함께 제기됐다. 이에 문서를 웹사이트 형태로 보기 쉽게 정리하는 방향과, 작은 PR + feature flag 활용을 검토하자는 의견이 나왔다.
- 운영 측면에서는 수요일 밤 미팅을 슬랙 스레드 공유로 대체하고, 전체 미팅은 토요일 오전 11시로 고정하기로 정리했다. 또 5월 2일(토) [SMTR25 'Reply High School' 팬미팅](https://news.nate.com/view/20260220n18787) 현장에서 게릴라 사용자 섭외와 인터뷰를 진행하기로 했다.

## 결정 사항
- 수요일 저녁 정기 미팅은 슬랙 스레드 공유로 대체한다.
- 전체 미팅은 토요일 오전 11시에 진행한다.
- 5월 2일(토) 오프라인 미팅을 [SMTR25 'Reply High School' 팬미팅](https://news.nate.com/view/20260220n18787) 현장(서울 올림픽공원 올림픽홀, 5/2~5/3 양일)에서 진행한다. 마케팅 메시지는 NCT 본진이 아닌 SM 신인 팬덤 타깃으로 차별화한다.
- 캐스팅 UX 보완, 그룹 페이지 진입 후 안내, 혼혈 옵션 정의 정리를 5/2 전 우선 과제로 둔다.
- 혼혈 옵션은 이 자리에서 확정하지 않고, 피그마 코멘트와 기획 확인을 먼저 진행한 뒤 구현 기준을 정한다.

## 주요 논의 내용 (실제 발화 인용)

### 1) UT 기준으로 가장 시급한 UX 병목
> **수지님**: “저 없이는 그냥 유저가 그냥 풀어놨을 때 그냥 스스로 찾아가기가 어려운 거예요. 뭐 채팅이나 뭐 이런 기능들을.”

> **수지님**: “장바구니에 상품을 넣었는데 다시 그 상품 목록에 들어왔을 때 ‘아, 들어갔다’라는 확신이 있어야 되잖아요.”

> **현준님 (줌 채팅)**: “로컬 스토리지로 처리하면 빠르게 가능할듯 하네요”

- 캐스팅 보드에 멤버를 담은 뒤 다시 탐색으로 돌아가는 흐름이 끊기고,
- 담긴 상태를 숫자나 뱃지처럼 즉시 확인할 수 있는 장치가 없어서,
- 사용자가 다음 행동을 주저하게 된다는 점이 핵심 문제로 정리됐다.
- 현준님이 줌 채팅으로 제안한 로컬 스토리지 처리 방식은 백엔드 도움 없이 프론트 단에서 보완 가능한 방향. 수지님이 명세를 정리해 슬랙 공유 후 5/2 이전 작업 가능 여부를 판단하기로 했다.

### 2) 발견 탭 = 그룹 생성 시작 구조의 모호함
> **현준님**: “발견 탭을 선택하는 것 자체가 아이돌 그룹 생성하는 그 사용자 액션이다 보니까 그 부분을 좀 더 명확하게 구분해야 되지 않을까 싶기는 해요.”

> **소연님**: “우리 발견 탭 누르면 바로 만들기 시작하는 거잖아요.”

> **수지님**: “이게 전반적으로 이 서비스가 무엇을 향해 가고 있는지, 어떤 것들이 있는지 온보딩 혹은 가이드가 부족한 것 같아요.”

- 지금은 발견 탭 진입만으로 그룹 생성 맥락이 시작돼 사용자가 ‘무엇을 시작했는지’를 파악하기 어렵고,
- 별도 버튼, 더 명확한 온보딩, 혹은 단계 안내가 필요하다는 공감대가 형성됐다.

### 3) 혼혈 / mixed 옵션 정의 불일치
> **지영님**: “기획 명세나 피그마 상에서는 캐스팅 플로우에서 인종을 선택할 때 혼혈 믹스드 키가 있는데, 그게 백엔드에서는 누락이 되어 있다고 들었어요.”

> **제형님**: “프런트에서 그냥 혼혈로 키를 주면 백엔드에서 랜덤으로 두 가지 인종을 섞든지, 아니면 애초에 프런트에서 인종 두 개의 키를 선택해서 백엔드에서 그 두 개를 조합시켜야 할지 이런 처리인 것 같습니다.”

> **영욱님**: “혼혈은 있는데 그게 어떤 인종의 혼혈인지는 없는 상태인 거죠.”

- 현재 기획/피그마와 백엔드 구현 기준이 맞지 않고,
- 사용자에게 보여줄 선택 방식과 내부 처리 방식을 함께 다시 정의해야 한다는 점이 분명해졌다.

### 4) 리더십 공백과 문서 / 의사결정 병목
> **수지님**: “소연님 부재가 너무 힘들고요. 의사결정을 해주는 사람, 그리고 UX 리서치에 대한 이해도가 있는 사람이 필요하다는 걸 많이 느끼고 있어요.”

> **수지님**: “제이님이랑 미진님이랑 저랑 바라보고 있는 이 서비스를 통해서 하고 싶은 것들이 여전히 다른 것 같아요. 비슷한 듯 다른데, 그래서 리더가 중요하다 그거를 많이 느끼고 있고요.”

- 팀원별 해석 차이가 커질 때 기준점이 부족해지고,
- 기능명세 → 와이어프레임 → 개발로 이어지는 연결 속도가 늦어지는 문제가 병목으로 언급됐다.

### 5) 문서 구조를 웹사이트처럼 보기 쉽게 만들 필요
> **현준님**: “처음 들어온 사람이 그 구조를 파악하고 문서를 정확하게 보기가 좀 힘들거든요.”

> **현준님**: “웹사이트 형태로 배포를 해서 계층 구조를 파악하기 쉽게 개편하는 게 어떨까 싶기는 해요.”

- 현재 docs 레포는 정보가 많지만, 처음 보는 사람이 구조를 따라가기 어렵고,
- 내부용 문서 포털 혹은 정적 사이트 형태로 정리하면 협업 속도를 높일 수 있다는 의견이 나왔다.

### 6) PR 단위 축소와 feature flag 활용 필요
> **은재님**: “현재는 백엔드가 먼저 머지 된 다음에 그 부분을 가지고 와서 프론트 브랜치에서 확인하는 식으로 방향이 바뀌어서, 그거를 조금 기다려야 된다고 느꼈던 것 같습니다.”

> **영욱님**: “PR을 더 쪼갤 수는 없을까요?”

> **영욱님**: “feature flag를 많이 활용을 해보는 것도 좋을 것 같습니다.”

- 백엔드 선행 머지 이후 프론트가 연동 확인을 기다리는 흐름이 체감 병목으로 공유됐고,
- 다음 스프린트부터는 작은 PR 단위와 feature flag를 활용한 병렬 개발을 검토하기로 했다.
- 작은 PR + feature flag는 [트렁크 기반 개발(TBD)](https://trunkbaseddevelopment.com/feature-flags/)의 두 축으로, 코드는 매일 main 머지(deploy)하되 사용자 노출은 플래그로 분리(release)하는 패턴. [Anthropic Claude Code 유출 사례](https://www.axios.com/2026/03/31/anthropic-leaked-source-code-ai)에서 [44개 피처 플래그](https://wavespeed.ai/blog/posts/claude-code-hidden-features-leaked-source-2026/)가 main에 포함된 채 운영되고 있었던 점이 업계 표준 사례로 인용됐다.

### 7) 미팅 운영 방식 변경
> **영욱님**: “수요일 미팅은 그냥 이번에 했던 것처럼 슬랙 스레드로 공유하는 걸로 대체하면 어떨까 싶습니다.”

> **영욱님**: “전체 미팅은 이렇게 토요일 오전 11시에 하는 걸로 하겠습니다.”

- 야간 미팅 부담을 줄이고,
- 공유는 비동기로 하고,
- 전체 정렬이 필요한 안건만 토요일 오전 전체 미팅에서 다루는 방향으로 정리됐다.

### 8) 5/2 오프라인 테스트 / 현장 반응 확인 아이디어
> **소연님**: “30일까지 끝내고 5월 1일이나 2일에 오프라인 미팅 가지시는 건 어떠세요.”

> **소연님**: “NCT 관련된 걸 해가지고 QR을 드려서 들어가 보실 수 있게끔 했는데… 증사 뒤에다가 QR 붙여서 들어가 보시라고 했었어요.”

> **수지님**: “약간 그런 전략이 좀 필요하겠네요. 그리고 그 현장에서 바로 얘기할 수 있을 만큼의 인터뷰를 준비한다든가.”

- 5/2 행사 정체: 회의 중 "NCT 콘서트"로 언급되었으나 소연님이 발화 도중 "응답하라 하이스쿨"로 정정. 실제 이벤트는 SM 다국적 신인 보이그룹 [SMTR25](https://namu.wiki/w/SMTR25)의 [Reply High School 팬미팅](https://news.nate.com/view/20260220n18787)([Mnet 응답하라 하이스쿨](https://namu.wiki/w/%EC%9D%91%EB%8B%B5%ED%95%98%EB%9D%BC%20%ED%95%98%EC%9D%B4%EC%8A%A4%EC%BF%A8) 후속 졸업 여행 컨셉, 5/2~5/3 양일 올림픽공원 올림픽홀)
- 5/2 전까지 버그와 콘텐츠를 최대한 정리해 두고,
- 공연장/현장 동선에서 QR, 기념물, 짧은 인터뷰로 실제 사용자 반응을 확인하는 방향이 이야기됐다.
- 마케팅 메시지는 NCT 본진 팬덤이 아닌 SM 신인 팬덤 타깃으로 차별화 권장. 5/3(일)도 추가 옵션.
